# Phases 3–4 — Human-scale 3D prototype and three-space integration

**Build state · 19 November 2026.** The briefing desk, library, and service counter have editable Blender masters and optimized GLBs. The 3D presentation is optional and the full semantic 2D path remains visible below it. Asset and engine checks pass; measured phone/laptop performance and observed learner comprehension remain open exit gates.

## Art and export contract

`assets/blender/*.blend` are editable masters generated by `scripts/make_rooms.py` in Blender 4.3.2. The contemporary kit uses a room shell, desk, paper cards, evidence tray, wall clock, and a stylized service worker with a seven-bone armature and rigidly weighted skinned body parts. The worker is a real-world service role, not a model avatar. All decisive source text remains in HTML; the card surfaces are visual props, not evidence.

The generator exports raw GLB masters to `assets/export/*.raw.glb`. `gltf-transform optimize` produces the runtime files in `public/models/*.glb` with `--compress false --flatten false --instance false --join false --simplify false --palette false`. Those settings preserve named clips, rig, and node pivots while avoiding a runtime meshopt decoder. `scripts/inspect_assets.py` checks skin, names, props, triangle count, clip duration, and file sizes and writes `assets/manifest.json`. `assets/briefing-preview.png` is a Blender workbench visual review, not a browser screenshot.

| Room | Raw GLB | Optimized GLB | Triangles | Clips |
|---|---:|---:|---:|---|
| Briefing | 97,196 B | 50,884 B | See manifest | `ReceiveQuestion`, `PlaceNotice`, `RemoveNotice` |
| Library | 182,120 B | 55,768 B | See manifest | `SearchNarrow` |
| Service counter | 86,356 B | 45,356 B | See manifest | `CalendarTimeout` |

The manifest is the source of exact counts and hashes after regeneration. All three assets contain one skin and no textures; materials use simple factors. The notice label is parented to the animated card. The counter timeout moves the terminal screen, not the notice. Named clips are 41 frames at 24 fps, approximately 1.708 seconds. Node names `ServiceWorkerRig`, `CurrentNoticeCard`, `EvidenceTray`, and `WallClock` are required by the inspection check. Keep origin and node names stable across exports.

To regenerate from a machine with Blender and the locked npm dependencies:

```sh
blender -b --factory-startup --python scripts/make_rooms.py
for room in briefing library service-counter; do
  cp "public/models/$room.glb" "assets/export/$room.raw.glb"
  npx gltf-transform optimize "assets/export/$room.raw.glb" "public/models/$room.glb" --compress false --flatten false --instance false --join false --simplify false --palette false
done
python3 scripts/inspect_assets.py
```

## Scene view model and cue contract

`sceneView(room, state)` derives the notice candidate/context flags, tool/proposal/booking statuses, candidate IDs, and semantic cue from the same scenario snapshot consumed by the HTML lesson. `sceneCue` maps only known event cues to named clips. The R3F scene may change prop visibility and play a clip; it cannot mutate the scenario. `RemoveNotice` corresponds to the context-removal event, `SearchNarrow` to a retrieval-strategy event, and `CalendarTimeout` to the Tuesday tool timeout. The public status and evidence panels update when `dispatch` returns, before any animation completes.

The optional view uses a fixed camera, no orbit controls, demand rendering, capped DPR 1–1.5, and no high-resolution textures. Pause, scrub, and skip change only the clip time. Reduced motion presents the static state. The full 2D panels remain mounted whether 3D is hidden, loading, unsupported, or failed. The viewport has a WebGL fallback and error boundaries around both the lazy module and asset loading.

| Blender preview | Generated and visually inspected | This checks composition, not browser rendering or accessibility. |
| GLB runtime parse | All three pass `GLTFLoader.parse` | Node test; no GPU rendering claim. |
| Modest Android phone FPS/memory | **Not measured** | Record model, browser, DPR, load time, frame-time distribution, memory/proxy, and battery/thermal observations during device test. |
| Integrated-graphics laptop FPS/memory | **Not measured** | Same test with keyboard, reduced motion, WebGL disabled, and failed asset path. |

The current art uses simple solid materials and low triangle counts. The large optional Three/R3F chunk and untested device behavior prevent a Phase 3 performance pass. Establish budgets from actual modest phone and laptop measurements; simplify geometry, clip count, or rendering stack if the lesson suffers. A synthetic or Blender workbench render is not a substitute for device measurements.

## Phase 4 parity and open review

The 3D room uses the existing briefing/library/counter states. Source eligibility, candidate lists, citation challenge, exact calendar request/response, timeout, proposal, comparison, replay, and experiment mode remain semantic HTML. Tests assert that removing notice changes state immediately, narrow search omits the candidate, the proposal stays `not_booked`, GLB clips exist, and the shared view model has the same facts as the scenario.

Manual checks remain: render on representative phone and laptop, inspect camera framing and prop visibility at each clip boundary, test WebGL/asset failure, check keyboard and screen reader with 3D open and closed, and observe learners explaining one failure in each space. The old notice is labeled superseded in the source-gate explanation but its full archival comparison view remains a later refinement. Do not call the Phase 4 go/no-go gate passed before these observations.
